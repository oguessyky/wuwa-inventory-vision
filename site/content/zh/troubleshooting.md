# 出了问题怎么办

## 安装

### 打开文件时弹出「安全警告 ... 未知发布者（Unknown Publisher）」

浏览器下载的 zip 会把里面每个文件都标成「来自互联网」。解压**之前**：右键点 zip → **属性** → 勾选 **解除锁定** → 确定，再解压。已经解压了的话，弹出来时可以放心点 **运行**：这些都是程序包自己的文件。

### 「wuwa」或 python 启动不了，提示被策略阻止

有些电脑的安全策略会拦截。用模块的方式运行，不要用 `wuwa`：

```
uv run python -m wuwa_vision live --identify
```

如果连 python 都被拦：从 python.org 安装 Python 3.12，再双击 **`1 安装 Setup`** 重新安装。

### 页面空白，或说页面没有构建

安装没有完成，双击 **`1 安装 Setup`** 再运行一次。

## 扫描

### 扫描一开始就停了，或说窗口不对

游戏本身要在最前面，浏览器里同名的标签页不算。启动后有 60 秒，按 **Alt + Tab** 切到游戏。离开游戏太久（2 分钟）会停下，读到的都保留。可以先检查一下它能不能找到游戏：

```
uv run python -m wuwa_vision windows
```

看到 `guard: window OK` 就可以开始扫描。

### 提示 F9 被占用，不肯开始

别的程序占了 F9，终端会列出空着的键。换一个键启动，比如：

```
uv run python -m wuwa_vision live --identify --panic-key F10
```

### 格子是红色的，或名字是问号

有些物品图标一模一样，只能靠点击分辨。在游戏里点一下这个物品，等扫描页顶部变成 **Ready**。点过一次就会记住。

### 新版本的物品没有名字

图鉴是旧的：到 **更新 → 图鉴** 点「从 Wiki 更新」，然后回到游戏点一下这些物品。

### 数量不对

在「库存」里点这个物品，点数字直接改，回车保存。改过的数字会一直保留，直到下次扫描读到它。

### 点了物品要等好几秒

正常：读右边的详情面板约 2.5–3 秒。看到 **Ready** 再点下一个。

### Mac 上什么都截不到

几乎都是「屏幕录制」没开：**系统设置 → 隐私与安全性 → 屏幕与系统录音**，打开你的终端，然后关掉终端再重新打开。可以这样检查：

```
uv run python -m wuwa_vision platform
```

## 服务器和手机

### 手机打不开这个网站

电脑（或服务器）和手机都要装好 Tailscale，并登录同一个账号。只有一台电脑的话，启动页面时不要加 `--local`，然后在手机上打开它印出的网址。

### 手机打不开扫描页

看终端里 `phone page:` 这一行。如果是 `phone page: not shared`，括号里就是原因，比如没装 Tailscale 或没登录；这时扫描照常进行，只是手机看不到。如果印出了网址，就看手机上的 Tailscale 有没有连上。这个网址只在扫描开着时能打开。

### 服务器的地址打不开

看 Tailscale 容器的日志有没有登录成功：`TS_AUTHKEY` 还是 `tskey-auth-PUT-YOURS-HERE`，或者密钥已经用过了，都不行。在 Tailscale 管理后台，`wuwa-server` 要显示为已连接。

### 几个月后服务器要求重新登录

这个设备开着密钥过期：在 Tailscale 管理后台把 `wuwa-server` 的 **key expiry** 关掉，再重新部署。

### 连接服务器时说「钥匙」不对

密钥是服务器存储路径里的 `data/server.key`。用 NAS 的文件管理器把它下载到「下载」文件夹，再双击 **`2 连接服务器 Connect server`**，钥匙那一步直接按回车：它会拿「下载」里最新的 `server*.key`。下载过好几次也没关系。

### 扫描时说「两边的版本不一样」

两边传送的数据格式变了：把扫描端和服务器都更新到同一个版本，见[更新](/update)。

### 服务器更新后启动不了：「joining network namespace of container: No such container」

只有还在用旧配置文件（三个容器）的项目才会这样。这三个容器共用一个网络，Docker 用容器 ID 把网络绑在其中一个上，那个容器一被换掉，其他的就指向了不存在的东西。在 NAS 的 Docker 应用里先**停止**这个项目，再**重新部署**（要重建：启动和重启都修不好）。数据都在项目的 `data` 文件夹里，不会受影响。

然后[改成一个容器](/server)，就不会再这样了。

### 启动时说「cannot join network namespace of a non running container」

同样是旧配置文件（三个容器）的问题：它们被同时启动或重启了。先**停止**项目，再**重新部署**，然后[改成一个容器](/server)。在那之前，尽量不要用项目的“重启”。

### 第一次下载图鉴很久

第一次要下载一千多个条目，主要时间花在等 Wiki 的服务器回应，不是网速。页面会显示进度和剩余时间；失败的条目会自动重试。以后每次只下载新增的。
